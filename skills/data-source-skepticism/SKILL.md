# 数据源怀疑主义

## 立场

**默认这批数据不是你以为的那个。** 不是说它有噪声 —— 噪声是明的、可以估的。真正会翻车的是**身份错误**：文件叫这个名、字段对得上、数值合理、跑得通，但它根本不是你以为的那个东西。

这类错误有个共同特征：**数据看起来完全正常**。没有缺失、没有异常值、没有报错。所以靠"看一眼数据质量"发现不了，只能靠专门去查身份。

代价也不对称：源头错了，下游所有结论一起错，而且错得整齐、看不出来。花一小时验身份，比事后追回十条已经说出去的结论便宜得多。

---

## 动作一：确认它是不是你以为的那个

### 先在自己地盘里找同源数据和既往勘察记录

**这一步排在所有统计指纹之前**，因为它给出的证据最硬、成本最低。

动手做指纹分析之前，先搜自己的仓库/知识库：**这个来源我们以前碰过吗？有没有同一家给的旧数据集、README、数据字典、当时的分析笔记？**

如果有旧的同源数据，**逐值比对新文件**（按主键对齐，看命中率和相符率）。这一条能直接回答统计指纹回答不了的问题：新文件是不是从同一条管线出来的、是不是被人重新加工过。

> 真实案例（本 skill 的评测里）：不带这一步的一版只做了统计指纹，还把"我需要旧数据的路径"推回给用户；而对照组去知识库翻出了同一家供应商的旧数据集和它的 README，把新文件按（单元, 日期）逐值对照，**全部命中却无一相符**，从而钉死"新文件不是从那条管线出来的"。**同源比对的判定力高于统计指纹。**

### 查取数代码，不是查文档

文档说的是"应该拿到什么"，代码决定"实际拿到什么"。**打开真正跑过的那段取数代码，逐个参数核对。**

**最危险的是没写的参数。** 一个没指定的参数会走默认值，而默认值经常是"我们替你挑一个最好的" —— 这类默认最要命，因为它返回的数据格式完全正常，只是来源不是你想的那个。

> 真实案例：抓数脚本的 URL 少了一个指定具体模型的参数。API 在这种情况下走一个叫「自动最优」的默认档 —— **按时段自动挑当时最好的那个模型拼起来**。此后连续几轮汇报都把这份数据称作原以为的那个源；实际拿到的是：近几年段是另一个更细的模型，早年段才是原以为的那个。一个漏掉的参数，让数据源根本不是以为的那个。

### 问数据源它到底给了你什么

很多 API 在响应里**回显它实际使用的参数**（实际取的格点坐标、实际匹配的记录、实际生效的版本、时区、单位）。几乎没人读这些字段 —— 它们恰恰是判定身份最直接的证据。

> 同一案例：响应回显的坐标间距，一个是干净的整数倍网格、另一个明显更密且不整齐 —— 直接坐实了用的是哪个。**"网格规整程度"这个判据比具体数值更可迁移。**

同理：导出文件的表头/元数据行、数据库的 schema 版本、CSV 的生成时间戳、文件名里的参数串 —— 都要看。

### 警惕"自动选最好的"在你的序列中途换了源

当来源会自动挑选时，它**可能在你的时间序列中途换掉选择**。这会在数据里留下一个系统性台阶。

**而这恰好会摧毁差分类的指标** —— 距平、同比、前后对比、A/B 差值。你以为在比"今年 vs 基线"，实际在比"模型甲 vs 模型乙"。

**规则**：任何跨时间/跨批次的差分指标，先确认整段序列来自同一个源、同一个版本。查法：按时间画出该量的分布，找台阶；或直接对每一段查一次身份。

## 动作二：独立复算，不信转述

**别人说"验证过了"不算数** —— 包括另一个 agent、包括上一轮的你自己、包括交接文档。

### 什么时候必须亲自复算

不是每条结论都值得复算。**触发条件是：这条结论会推翻你一直在说的话，或者会改变一个决定。**

> 真实案例的原话：「这是一连串重大发现，最关键的一条会推翻我前面几轮反复说的话——**所以我必须亲自验证，不能只信工作流**。」

一条结论越是让你意外、越是要改口，越要自己动手。舒服的结论可以先放着，扎心的结论必须当场核。

### 怎么复算：挑一个有判别力的量

不要做"整体相关"这类模糊比较 —— 两个相似的数据源整体相关都很高，区分不开。

**挑一个在候选源之间差异极大的量，直接对比数值。** 判别力来自差距，不来自样本量。

> 真实案例：拿盘上的生产数据算出某个单元的整段累计量 = 508.3，与候选源 A 抓下来的 508.3 **精确到小数点后一位一字不差**，而候选源 B 是 283.1。一锤定音，不需要任何统计检验。

好的判别量的特征：是累计/汇总量（放大差异）、在候选源之间量级不同、能从现有数据直接算出来（不需要重新抓）。

### 再找一个独立信号佐证

一条证据可能是巧合。**用一条机制完全不同的证据交叉确认**（上例：数值精确相等 + 回显格点间距）。两条独立证据同时指向同一结论，才算钉死。

### 钉死之后，立刻列出爆炸半径

发现源头错了，**第一件事不是修，是列清单**：哪些已经说出去的结论依赖了它？哪些文档、哪些图、哪些给别人的答复？

> 真实案例里，发现后立刻做的是：明确认错（"我之前说错了"）→ 指出根因（哪个文件哪一行）→ 列表说明每个时段实际是什么 → 逐条说明这对已交付的那份报告意味着什么。

## 动作三：从数据特征反推它是实测还是算出来的

有人说这是"实测数据"、"一线实况"、"用户真实行为"，**不要信标签，去数据里找证据**。模型产出/合成数据/推导字段都会留下指纹：

| 指纹 | 怎么查 | 说明什么 |
|---|---|---|
| **列间存在严格函数关系** | 检查 `C = A − B`、`比率 = X/Y` 是否**每一行都精确成立** | 该列是推导的，不是独立观测。推导列不带新信息，也不能当独立变量用 |
| **某列与一个确定性计算精确吻合** | 与理论/天文/公式值算相关，看是不是 1.000000 | 它是算出来的量，不是测出来的 |
| **分类标签与数值是 100% 的函数关系** | 按标签分组看数值范围有无重叠 | 标签是从数值反推的，不是独立判断/独立观测 |
| **不同单元的序列完全相同** | 对所有单元两两比较，数重复组 | 分辨率碰撞 —— 上级单元取一个值复制给了下属各单元。名义 N 远大于有效 N |
| **字段清单恰好等于某个公开 API 的返回字段** | 把列名与候选 API 文档逐项对照（清单里往往还含那些只有模型才会齐全输出的量） | 数据是那个 API 的原样搬运 |
| **完全矩形、零缺失、零重复** | 看有没有痕量值、缺测标记、质控码、观测点编号 | 真实采集不可能这么干净。**正向验收判据**：真实数据应当带缺测标记 + 质控码 + 观测点编号，数值应有痕量与量级跨度 |

> 真实案例：一批号称"单元级实测"的数据，用五条证据判定为模型产品 —— 某个理论上可离线算出的量与公式值逐日吻合到 r=1.000000；文字标签与数值列是 100% 函数关系（标签写"无"的日子数值恰好全是 0）；某列严格等于另两列之差；数百个单元里近四成的序列互相完全相同（上级单元取一个值复制给了下属各单元）；字段清单是某公开日接口的原样搬运。

**这件事的实际后果**：如果两批数据其实是同源或同类产品，那么"用 B 验证 A"就不是验证，只是**敏感性检验**。要诚实说明：这批材料回答不了"谁更接近真实"这个问题。**知道你的比较能证明什么、不能证明什么，和做这个比较同样重要。**

## 动作三点五：适配性 —— 就算它是真的，能不能回答你的问题

真伪和适配是**两个独立的否决维度**。数据完全真实、完全可信，仍然可能一条结论都支撑不了。真伪查完之后，再过一遍这四项，**任何一项不过，这份数据就用不了**：

| 检查 | 问什么 | 不过会怎样 |
|---|---|---|
| **空间/对象覆盖** | 它覆盖的单元，包含你要分析的那些吗？ | 数据再准，测的不是你的对象 |
| **时间窗** | 它的时间范围盖得住你需要的窗口吗？ | 只能算部分窗口，结论口径被迫改变 |
| **基线/对照期** | 要算距平、同比、提升，有没有足够长的基准期？ | 只能报绝对值，报不了"相对于常年/对照" |
| **字段口径** | 关键字段的定义与你下游的计算一致吗（公式、参数取值、单位、聚合方式）？ | 算出来的量和你以为的不是一回事 |

> 真实案例：一份数据本身没问题，但四条全踩 —— 覆盖的行政单元不含任何一个目标站点、时间范围盖不住整个观察窗口、没有建距平所需的基准年、且缺一个关键字段导致下游一个逐日累计的派生指标口径不可比。**先查适配性，能在花力气验真伪之前就把它否掉。**

顺序建议：**先适配性（便宜、常常直接否掉），再真伪（贵）。** 上面把真伪写在前面是因为它更反直觉，但实际执行时适配性可以先跑。

## 动作四：量化天花板，别只问"能不能更好"

有人问"数据能不能更准/更细/更多"时，**不要直接去优化**。先算清楚：**就算全做对，天花板在哪？**

这个问题比"能不能更好"有用得多，因为答案经常是"改了也白改" —— 而这个答案能省下几周工作。

分四步：

1. **物理/机制天花板**：被测对象本身的尺度是多少？现有手段能分辨到什么程度？换更好的手段能不能跨过那个尺度？（例：要观测的现象本身的尺度，比现有手段和候选手段都小一个量级 —— 那么换手段仍然分不开。）

2. **统计天花板**：**用独立单元数做功效分析** —— n 个独立单元下，效应要多大才能检出？现有最强的信号有多大？
   > 真实案例：独立单元只有 26 个，偏相关要 |ρ|≥0.396 才显著，而实测最强只有 −0.297。**差的是相关系数本身，不是数据质量。** 把数据源换得再好，也改变不了任何结论。这一条直接终结了"要不要换数据源"的讨论。

3. **噪声预算**：把所有误差源放在一起**比大小并排序**。**现在最大的噪声源是哪个？修哪个收益最大？** 不排序就优化，通常在修第三大的那个。
   **误差源清单里必须包含"你自己的分析口径"** —— 这是最容易漏的一项，因为大家默认口径是给定的、只有数据才有误差。
   > 真实案例的排序结果，和所有人的直觉相反：第一名是**分析窗口的定义**（换一个同样合理的时间窗，关键相关系数横扫 Δρ≈0.43）；第二名是坐标定位误差（0.03–0.07）；数据分辨率只排第三（0.10）。也就是说，**换更贵的数据源去解决第三名，而第一名是一行口径定义**。

4. **用手上的数据模拟降级**：想知道"换成历史更短的源会损失多少"，不用先去换 —— **用现有长序列自己截短，算出差多少**。这类代理实验通常几十行代码，**比真的换一遍便宜两个数量级**。

输出要做成**决策形状**，不是论文形状：每个选项给出「收益 / 成本 / 结论（值得做 / 有条件值得 / 不值得 / 做不到）」，并正面回答最初被问的那句话。

## 动作五：留意旁逸斜出的线索

**审数据源时顺手挖出的问题，经常比原任务值钱。**

> 真实案例：本来只是评估"要不要换数据源"，顺手查出定位表里有三分之一的点用了上级单元的中心而非实际位置、4 个点归属挂错、还有 3 个不同的观测点被压成 1 个共用一个值。**这些对结论的影响远大于换数据源** —— 而它们不在任务书上。

规则：**看到不合常理的东西就记下来，哪怕它不是你在找的。** 排查完当前任务再回头看这张清单。不合常理包括：数量对不上、名字重复、精度突变、分布有台阶、某几行特别整齐或特别不整齐。

## 红旗表

| 想法 | 现实 |
|---|---|
| 「数据跑通了、没报错，应该没问题」 | 身份错误不会报错。跑通只说明格式对。 |
| 「文档写着这是 X」 | 文档写的是意图。去看取数代码的实际参数。 |
| 「工作流/同事/上一轮的我说已经验证过了」 | 会改口的结论必须自己复算。转述不算证据。 |
| 「他们说是实测数据」 | 去数据里找模型指纹：推导列、完全重复的序列、太干净。 |
| 「两个源整体相关 0.9，差不多」 | 挑有判别力的量看具体数值。整体相关区分不开同类产品。 |
| 「用 B 验证了 A，结论稳」 | B 和 A 同源吗？同源的话那是敏感性检验，不是验证。 |
| 「换个更细/更准的源肯定更好」 | 先算天花板和噪声预算。最大噪声源可能根本不是数据精度。 |
| 「这批数据完全没有缺失，质量真好」 | 真实采集不会这么干净。太干净是嫌疑，不是优点。 |
| 「这个问题不在我这次任务里，先不管」 | 记下来。顺手发现的问题经常比原任务重要。 |
| 「最大的噪声源当然是数据精度」 | 把你自己的分析口径也放进误差清单。它经常排第一。 |
| 「先做统计指纹分析」 | 先搜自己地盘有没有同源旧数据和 README。同源逐值比对判定力更高、更便宜。 |
| 「数据是真的，可以用了」 | 真伪和适配是两个独立否决维度。覆盖、时间窗、基线期、字段口径再过一遍。 |
| 「需要旧数据的路径才能比对」 | 那是你能自己搜到的东西。别把可自查的事推回给人。 |

## 与其他 skill 的关系

- 数据可信之后，**数字怎么说** —— 见 `statistical-caliber`（口径、伪重复、多重比较、不越界）。
- 用多 agent **系统性排查**一批数据或一份分析 —— 见 `verified-survey`。
- 把核实过的数字**绑进交付物、防止静默过期** —— 见 `generated-deliverable-discipline`。
- 要去**外部找一批数据**时，先跟领域负责人对一句来源形态再撒并行舰队 —— 见 `long-task-collaboration`。
- 数据可信之后、算数之前：**这张表哪些行可比、几个独立单元** —— 见 `analysis-groundwork`。
