# 分析地基：从一张原始表到可比的记录

## 这一段为什么需要单独有人管

- 「这批数据可不可信」是**上游**的问题（数据源怀疑主义）。
- 「这个数能不能这么说」是**下游**的问题（口径纪律与表达）。
- **中间这一段没人管**：我手上有张表，我正要决定谁和谁可比、几行算一个独立单元、哪些行进哪些行出。

这一段做错的特征是：**下游所有检查都发现不了**。数字算得没错、口径标注得也对、图也画对了 —— 只是"哪些行可比"这个前提在出生时就错了，而它不出现在任何一个结论里，所以没有任何一条核验会去攻击它。

> 两次最贵的翻盘都发生在这一段：一次是编码语义读错，"干净对比"从 55 条变成 96 条，头条结论在**不成立（p=0.055）↔ 成立（p=0.0019）之间翻了个面**；一次是缺失值拼出一个不存在的分组，独立单元数从 36 修正为 35，一整组分组统计作废。
>
> 两次都不是"数据源不可信"，也不是"这个数不能这么说"。

---

## 一、开工前：逐列点名

**把原始表的列逐列过一遍，明确标出"我从来没打开看过"的那几列，并把它们登记为一级风险。**

**为什么**：人会自然地只打开"看起来和结论有关"的列。而决定**记录之间是否可比**的元数据列（配对关系、批次号、唯一性标记、试验设计代码）长得**不像分析变量**，于是被跳过。一旦跳过，所有下游统计就建立在"每行都是独立可比的观测"这个从未被验证过的默认上。

> 真实案例：一份已经产出"这是全数据唯一的因果结论"的分析，复盘时才发现源表里有两列专门记录"这条对比是怎么配对的"，**从头到尾没被打开过**。打开后发现只有一部分记录是"两边条件相同、只差干预"，头条的因果成色当场降级。

对每一列问：它是**分析变量**、**分组/配对元数据**、还是**说明性文本**？第二类决定可比性，必须逐个打开看取值。

---

## 二、地基判断按"爆炸半径"分两档，承重的停下来等人答

盘点完口径问题，**不要把二十个问题一起抛出去**。分两档：

- **承重 —— 现在就要拍板，改了要返工**：纳入排除规则、分组键、配对定义、主口径。**每条附上"如果这个判断反了会怎样"**，然后**停下来等人回答**。
- **可延后 —— 我按这个默认值走**：排序、配色、命名、展示粒度。每条用一行说明你要采用的默认值，然后继续。

**为什么分档**：口径决策的返工成本极不对称。分组键或纳入标准一变，所有下游数字、图、文案全部作废；配色改了就改了。不分档，人只会回答看得懂的那几个。

承重项的写法范例：

> **「35 个独立单元」是我用多列指纹去重推出来的，不是源数据里的真实编号。**
> 数据里其实有几列 ID 我没用过。指纹去重有两个方向的错：两个不同单元的取值恰好相同 → 被错误合并；同一单元两次记录略有差异 → 被错误拆开。
> **后面三页的伪重复叙事、功效曲线、明年的样本量规划，全建立在这个 35 上。**

---

## 三、编码字段的语义只能问人，不能从取值分布反推

取值长得像"两组不同"，**不代表它们真的不同** —— 编码常常只记录"两边差异的那一截"，省略了两边共有的部分。这种省略**从数据里完全看不出来**，只有写这张表的人知道。

**问之前先把分岔的两种解释各自算出来**，让对方在**已经量化的后果**上判断，而不是在术语上判断：

> 「如果这个编码的含义是 A，纳入 N₁ 条，结论是 X；如果是 B，纳入 N₂ 条，结论是 Y。是哪个？」

**为什么这么问**：领域专家扫一眼就能否掉，不需要先看懂整个分析。而问"这一列是什么意思"，他要先猜你为什么问。

> 真实案例：从配对编码判定"只有约 1/3 的记录是干净对比"，据此把主效应重算成不显著并**写进了报告**。产品负责人随后一句话解释了这些编码代表的实际操作方式 —— 若干组"看起来不同"的对照其实与处理端同底、只差干预。重判后干净集从 55 条扩到 96 条，主效应从 p=0.055 变成 p=0.0019。**同一批数据、同一个"只留干净对比"的原则，仅因编码语义读错，头条在成立与不成立之间翻了个面。**

## 四、分组键：推断出来的必须当成推断

如果"有几个独立单元"是你**推断**出来的（多列拼指纹、字符串匹配、规则归并），而不是源数据里的真实 ID：

1. **在文档里显式标注它是推断**，不要让读者以为是真实编号。
2. **说清两个方向的误判**：该合的没合（高估单元数）、不该合的合了（低估单元数）。
3. **构造键之前，先剔除任何构成列有缺失的行。**

第 3 条是硬坑：**缺失值序列化之后彼此相同**，于是所有缺数据的行会被静默并成同一个桶 —— 凭空多出一个不存在的"幽灵组"，并被带进每一处按组的统计。

> 真实案例：用十几个指标拼指纹推断独立单元数，全量去重得到 36 个签名；只保留检测完整的记录后是 35 个。差的那一个，是十几条缺检测的记录因为**指纹全为空、彼此相同**而被并成的幽灵组。修正后组层相关从 ρ=−0.30 / p=0.073（"差一口气"）变成 ρ=−0.259 / p=0.133（明确不成立）。

**"有多少个独立单位"是所有聚类标准误、功效计算、样本量规划的地基。** 它错了，上面全塌。

## 五、同一份文档里两处计数不一致 = 报警器

**同一个计数出现了两个值，立即回原始数据查清，不许当成四舍五入或笔误糊过去。**

两处不一致意味着两段代码用了两套口径，**而其中至少一套是错的** —— 错的那套通常还在支撑某个结论。

这类不一致还有个特殊价值：**它是非技术读者唯一能在不看代码的情况下发现口径 bug 的入口**。

> 真实案例：正文一处写"35 个独立单元"，另一处的相关性分析括号里写"（36）"。产品负责人在一长串问题里顺手问了一句"我们不是只有 35 吗？怎么变成 36 了"。回查发现是缺失值造成的幽灵组，连带修正了三段结论文案和一整组分组统计。

## 六、把清洗判断做成正交开关，整张网格报出来

每一个清洗/校正判断做成一个**正交开关**（纳入范围 × 聚合层级 × 是否做某项校正…），跑成一张网格，**整张报出来**，不要挑一格当答案。

**为什么**：两个都合理的清洗选择组合起来，结论强度的跨度可以从 p<0.001 一路到 p>0.1。挑其中一格写进结论，就是在无意识地做选择性报告。而并排列出网格，**格与格之间的落差本身就量化了每个判断带来了多少证据强度**。

> 真实案例的 2×2（聚合层级 × 是否去偏校正）：ρ=−0.415 (p<0.0001) / −0.247 (p=0.0034) / −0.369 (p=0.029) / −0.259 (p=0.133)。最松的格子极显著，最严的格子不成立。

只有一格显著、其余不显著时，**正确的写法是"某某层显著、去重后不显著"，不是"显著"**。

**交互产物上更好的落法**：把口径做成**选择器**，一次只画一格、切换时做缓动位移。读者不必记住哪一行是哪个口径，而是**直接看见信号是变强还是塌掉** —— 比静态并排更有说服力。（起因是一句真实反馈：「观看者需要记住从上到下的口径，这不行」。）

## 七、换口径之后，所有派生统计必须同口径重算

主结论一旦换口径，**所有派生的子集/分组统计必须在同一口径下重算并逐条复核**。

**为什么**：换口径时人的注意力全在头条数字上，分组表、分档明细、"几个子群方向一致"这类**支撑句**往往还是旧口径的残留。而这些支撑句恰恰是读者用来判断结论稳不稳的依据 —— 一旦是旧口径的，等于**用假象给真结论背书**。

> 真实案例：头条换成了校正后的相关系数，但"四个子群单独算全是同向"这句支撑话仍是未校正的数。重算后其中一个子群从 ρ=−0.51 变成 +0.01 —— 整条支撑句消失，改写成"2 个成立、1 个方向对但不显著、1 个完全没有"，并在方法框里补一句"未校正时它是 −0.51，那一整条都是假象"。

执行时用**带断言的批量替换**（旧串找不到就报错），防止静默漏改。

## 八、派生变量：针对一个具名假象来选定义，并写下"它不是什么"

两个都"合理"的定义里，往往只有一个**不会与被解释变量在数学上耦合**。选错了就会把纯粹的数学假象报成发现。

**在方法说明里写出你规避的是哪个假象。**

> 真实案例：考察"基线水平 vs 提升幅度"时，用基线本身当横轴会因为分母耦合造出**必然的**负相关；改用两臂平均值当横轴可以避开。原始 ρ=−0.44 里约四成是假象，校正后 −0.27。

同时，**在定义处写下它不是什么** —— 不要让变量名把口径偷偷升级成一个更强的断言：

```python
# 基线水平 ＝ 两臂结果的平均（避开与提升幅度的分母耦合）
# 注意：这是实测产出，不是"底子好坏"——低也可能来自其它原因，别用那个更强的名字
```

## 九、交付前把口径收敛成一个具名脚本

探索期的口径散落在一次性脚本里，每个脚本各读一遍原始表、各写一遍筛选条件 —— **口径于是有 N 份互不相同的副本**，这正是"头条用新口径、分组表用旧口径"的温床。

交付前收敛成一个具名的「原始 → 分析表」脚本：

- 口径落成**具名列**（布尔列、分组列），不要散在各处的 filter 条件里
- 每个判断带**一行为什么**的注释
- 结尾 `print` 出**条数分档 + 头条数字**，并把期望值写死在括号里做 sanity check
- 下游只读这层中间产物，**不再各自读原始表**
- 然后**从零重跑整条流水线**（prep → 生成 → 体检）做冒烟测试

sanity print 的形态：

```
d2.pkl: 153 条 | 干净 96 / 跨牌号 57
  全部   +2.68%
  干净   +2.57%
复核 干净96: +2.57%  p=0.0019  (应为 +2.57% / 0.0019)
```

括号里的"应为"是关键 —— **口径漂移会在每次重跑时被人眼当场抓到**，而不是等读者发现两个数对不上。

## 十、纠正之后，把纠正本身写进交付物

口径错误会**重复发生在下一个读这份数据的人身上**，因为原始表本身不会变得更清楚。

- 表头**写死**两边各是什么，不要沿用源表的简写
- 易误读的编码同时给出**反面提示**：「**不是** A 对比 B」
- 明确列出**仍然依赖领域确认的那一条推断**及其量化后果：「如果这条也不对，那 N 条要移出」

> 真实案例的原话：「编码词典里那条也加了反面提示：**不是"A 对比 B"**……**这正是我上一版栽的地方，写出来省得下个人再读错。**」

## 红旗表

| 想法 | 现实 |
|---|---|
| 「这几列跟结论没关系，不用看」 | 决定可比性的元数据列长得就不像分析变量。逐列点名。 |
| 「这个编码的意思很明显」 | 编码常只记录"差异的那一截"。从数据里看不出来，只能问人。 |
| 「问一下这列什么意思」 | 先把两种解释各自算出来，让对方在量化后果上判断。 |
| 「去重完有 36 个单元」 | 构成列有缺失的行会拼出同一个键，并成一个幽灵组。先剔除再去重。 |
| 「这两处数字差 1，四舍五入吧」 | 两套口径至少错一套，而错的那套在撑着某个结论。立刻回原数据查。 |
| 「几种清洗方式里选最合理的那个」 | 做成正交网格整张报出来。格与格的落差本身就是信息。 |
| 「头条口径改了，改一下那个数就行」 | 所有派生的分组统计都要同口径重算，否则用假象给真结论背书。 |
| 「给这个变量起个好懂的名字」 | 名字会把口径偷偷升级成更强的断言。在定义处写下"它不是什么"。 |
| 「分析做完了，脚本先留着」 | 口径有 N 份副本就会漂移。收敛成一个具名脚本 + sanity print。 |
| 「口径搞对了，改过来就行」 | 把纠正和当初为什么读错都写进交付物，否则下一个人照样栽。 |

## 与其他 skill 的关系

- 这张表**本身可不可信**（是不是你以为的那个来源、是不是实测）—— 见 `data-source-skepticism`。
- 地基定了之后，**数字怎么报、怎么讲给非统计读者** —— 见 `statistical-caliber`。
- 承重项**怎么交给人拍板** —— 见 `long-task-collaboration`（只问对方凭身份能答的，先讲清再问）。
- 用多 agent **系统性排查**这些地基假设 —— 见 `verified-survey`（把"纳入规则"和"分组键"显式放进核验对象清单）。
