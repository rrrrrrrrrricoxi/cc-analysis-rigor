# cc-analysis-rigor

把一批实验/试验数据做成一份**经得起追问**的交付物。六个方法 skill + 一个冲刺命令。

从一次真实的多省田间试验分析里沉淀出来（153 条对比记录 → 12 页 HTML 主报告），但**skill 本身不含任何领域内容** —— 换成 A/B 测试、门店促销复盘、临床数据、设备可靠性试验，一样用。

## 装

仓库本身既是 marketplace 也是 plugin：

```
claude plugin marketplace add rrrrrrrrrricoxi/cc-analysis-rigor
claude plugin install cc-analysis-rigor@cc-analysis-rigor
```

本地开发时可以把第一行换成仓库的本地路径。

## 六个 skill 各管一段

数据分析出错的地方不是均匀分布的，它们集中在六个交接口，每个 skill 守一个：

| skill | 什么时候触发 | 守的是哪一类错误 |
|---|---|---|
| **analysis-groundwork** | 拿到原始表，**还没算任何数** | 谁和谁可比、几行算一个独立单元、纳入排除。**错在这里的，下游所有检查都发现不了** |
| **data-source-skepticism** | 数据不是你自己生成的 | 数据根本不是你以为的那个源；或者它是真的，但回答不了你的问题 |
| **statistical-caliber** | 一个数**正要被说出口** | 口径没标、伪重复、扫描出来的假阳、p 值配错检验、样本不够却下了结论、真信号被混杂盖住却写成"没关系" |
| **generated-deliverable-discipline** | 要改脚本生成的产物 | 结论对但产物错，而且是**静默**错：手改被覆盖、数字静默过期、旧结论只改了一半、图替读者下了结论 |
| **verified-survey** | 要派多 agent 查一件事 | 一堆看起来有道理、但没人试图推翻过的发现 |
| **long-task-collaboration** | 正要开口问人 / 正要汇报 | 问了对方没 context 的问题、只改被点到的那一处、承诺被小修复顶掉 |

六个之间互相 `link`，触发词已做过去重，正常不会互抢。

## 一个命令

```
/analysis-sprint
```

开一轮完整冲刺时用。它不重复 skill 的内容，只负责**排顺序、设停止点** —— 特别是关卡一那个"承重口径先停下来等人拍板"的关卡，那是整条链上最省钱的一次等待。

## 这套东西的来历

它不是设计出来的，是**踩出来的**。几条留在 skill 里的教训：

- 一个漏掉的 API 参数，让"我们用的是某某数据源"这句话错了好几轮汇报 —— 而数据看起来完全正常。
- 缺失值在拼接分组键时彼此相同，静默并出一个不存在的分组，独立单元数从 35 变 36，一整组统计作废。
- 编码语义读错，"干净对比"从 55 条变 96 条，头条结论在 **不成立 (p=0.055) ↔ 成立 (p=0.0019)** 之间翻了个面。
- 一页排版塌了，自动体检报 0 问题、一整套多 agent 验证流程全绿，最后是**收件人自己贴了张截图**才发现。
- 27 项候选指标里最强的那个 p=.006，看着很硬；FDR 之后一个都没通过。

## skill 自己也过了一遍这套方法

初稿写完之后，用 `verified-survey` 的四段式审了自己：4 个审查 agent 逐条回原始 transcript 和 workflow 脚本核对，1 个完整性批评者看整套边界。**推翻了初稿里若干条编造的"真实案例"和走样引文**，也改正了几处实质错误（验证顺序把秒级断言排在了几十秒的浏览器体检之后；噪声预算把派活时的候选清单当成了结论）。

行为评测（读了 skill vs 没读的对照组，同一批任务）：

| 用例 | 读了 skill | 对照组 |
|---|---|---|
| 统计口径 | **6/6** | 3/6（把趋势检验的 p 当成了分档提升的 p） |
| 数据源指纹 | 6/6 | 6/6 |
| 生成型产物 | 4/5 | 4/5（对照组反而更深，据此补了两节） |

第三行是有意留着的：**这套方法不是每个场景都赢**，赢的地方和平的地方都写在这儿。
