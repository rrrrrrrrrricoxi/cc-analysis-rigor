# 分析冲刺

用户要把一批实验/试验数据做成一份能拿出去讲的交付物。这个命令负责**排顺序、设关卡**，具体方法在六个 skill 里，到哪一步读哪个。

## 开场：先摸清楚，别急着算

问清楚（或从材料里读出来）这四件事，**缺哪件就问哪件**：

1. **原始数据在哪、什么形态**（几张表、多少行、谁给的）
2. **这批数据要回答什么问题**（一句话，业务语言）
3. **交付物是什么形态**（一页纸？deck？HTML 报告？给谁看？）
4. **有没有上一版**（有的话，它的口径是什么、哪些结论已经对外说过）

第 4 条最容易漏，而它决定了后面所有"两版数字对不上"的争论。

---

## 关卡一：地基（还没有任何数字）

**读 `analysis-groundwork`。**

产出一份**按爆炸半径分两档**的清单：承重的（纳入排除规则、分组键、配对定义、独立单元数）和可延后的。

🚩 **这里是第一个停止点**：承重项**逐条附上"如果判断反了会怎样"，然后停下来等人回答**，不要边问边做。呈现方式见 `long-task-collaboration`（只问对方凭身份能答的；引用了他还没过目的中间产物的问题，先讲清再问）。

---

## 关卡二：数据源身份与适配性

**读 `data-source-skepticism`。**

数据不是自己生成的，就先过这一关：先搜自己地盘有没有同源旧数据和 README → 查取数代码的实际参数 → 适配性四项（覆盖 / 时间窗 / 基线期 / 字段口径）→ 需要时做指纹判定。

**适配性先跑**，它便宜且常常直接否掉一份数据。

---

## 关卡三：算，并且判断每个数能不能这么说

**读 `statistical-caliber`。**

按它的清单逐条过（分配单元 → 子集与 n → 层级/伪重复 → 混杂 → 多重比较与另外三个分组陷阱 → p 值配对 → 自洽性 → 样本强度 → 命名 → 绑定）。

主口径**只定一个**，全文头条统一用它；其余档进阶梯表和附录。

---

## 关卡四：讲给谁听

**还是 `statistical-caliber` 的「讲给谁听」一节。**

最外层通俗、不出现裸的 p/r/区间端点；每个统计概念可下钻，下钻第一句永远回答**"为什么需要这一步"**。给用到的方法各做一张方法卡，例子必须来自本次数据。

---

## 关卡五：做产物

**读 `generated-deliverable-discipline`。**

数字从数据文件渲染、不要手打；改动走生成脚本、不改产物；改完按固定顺序验证（重跑 → 语法 → 数值断言 → 结构体检 → 逐页看图 → 交互实测 → diff）。

图表按「有没有替读者下结论」那一档先过一遍，再过逐项清单。**选型和配色用 `dataviz`，这里只管验收。**

---

## 关卡六：交付前核验

**读 `verified-survey`。**

规模由**正交的取证方向数**决定，不是由"想多认真"决定。装得下就自己读，别起编排。

要起编排时，把**纳入规则和分组键也显式塞进核验队列** —— 它们不在任何 findings 里，默认没人会去证伪。最后留一个完整性批评者。

---

## 全程

- 每次汇报固定挂一段「**还欠着的**」，下一轮从它开始（`long-task-collaboration`）。
- 子 agent 的结果**不许原样转发**，重新综合成分层 + 编号 + 带位置和改法的清单，末尾交还调度权。
- **改口径就全文重算派生统计**，别让旧口径的支撑句给新结论背书。
- 说错了就明说哪里错、根因是什么、影响了哪些已经说出去的结论。
